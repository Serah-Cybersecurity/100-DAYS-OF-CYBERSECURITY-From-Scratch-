# Windows Logging Architecture & Core Event IDs - Day 12 Notes

## 1. Core Windows Logging Definitions (in my own words)

* **Event Log:** A centralized, structured database file (stored in `.evtx` format) managed by the Windows Event Log service that records system, security, and application activities over time.
* **Event Provider:** The underlying software component, driver, or application subsystem responsible for generating and submitting raw event data to the operating system when a specific action occurs.
* **Channel:** The designated routing category or pathway used to organize events logically (e.g., the `Security` channel or `Application` channel) so administrators and security tools can filter them easily.
* **Event ID:** A specific numeric code assigned by an event provider to identify an exact type of occurrence (e.g., Event ID `4624` for a successful logon). Context (the provider and log channel) is essential to interpret it accurately.
* **Event Record:** The individual data entry or data structure containing all metadata associated with a single occurrence—including timestamps, Event ID, computer name, user accounts, process details, and source IP addresses.

---

## 2. Log Comparison: Security Log vs. System Log

The **Security Log** and the **System Log** serve completely different operational purposes within a Windows environment. 

The **Security Log** tracks authentication activity, account management, and events generated by configured security auditing policies. It is the primary log monitored by SOC analysts to detect brute-force attempts, unauthorized logons, and privilege escalation. 

In contrast, the **System Log** records events generated directly by core Windows operating system components, hardware drivers, and background services. It is utilized to diagnose service failures, system errors, and OS operational state changes. 

While both logs are critical during an investigation, they monitor entirely different layers of the operating system; never assume a security-relevant event will appear in the Security log alone.

## 3. Key Security Event IDs Reference Table

| Event ID | Log Channel | Category | Description & Security Relevance |
| :--- | :--- | :--- | :--- |
| **4624** | Security | Logon / Authentication | **Successful Logon:** Records when a user successfully logs into a system, identifying the logon type (e.g., interactive, network, Remote Desktop) and user account. |
| **4625** | Security | Logon / Authentication | **Failed Logon:** Records unsuccessful authentication attempts. High volumes of this ID are a primary indicator of brute-force or password-guessing attacks. |
| **4672** | Security | Privilege Assignment | **Special Privileges Assigned:** Logged whenever a user logs on with administrator-level or special system privileges (e.g., `SeDebugPrivilege`). |
| **4688** | Security | Process Tracking | **New Process Created:** Records when a new process is spawned. When command-line auditing is enabled, it reveals exact commands and scripts executed. |
| **1102** | Security | Audit Log Tampering | **Audit Log Cleared:** Logged when the Windows Security Event Log is manually cleared. This is a critical red flag indicating an adversary trying to cover their tracks. |
