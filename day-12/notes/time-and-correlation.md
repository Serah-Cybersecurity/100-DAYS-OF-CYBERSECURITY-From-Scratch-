# Time Zones, Correlation & Event Context Notes - Day 12

## 1. UTC Versus Local Time (`Z` Timestamps)
* **Definition:** Windows Event XML timestamps commonly record time in Coordinated Universal Time (UTC), denoted by a trailing **`Z`** (e.g., `2026-10-30T10:00:00Z`). Event Viewer may adjust these to local machine time zones.
* **Forensic Significance:** Never compare raw timestamps across systems in different geographic regions without normalizing them to a common baseline (UTC). A time delta could simply be a timezone offset rather than delayed activity.

---

## 2. Event Record ID Limitations
* **Definition:** A sequential integer assigned to records as they enter a specific log channel.
* **Forensic Significance:** Record IDs are strictly **log-specific**, not universal. Record ID 50 in the System log is entirely unrelated to Record ID 50 in the Security log.

---

## 3. Logon ID Correlation (Session Tracking)
* **Definition:** A unique identifier (e.g., hexadecimal value `0x3E7`) generated by the Windows security subsystem upon authentication, persisting for the lifespan of the logon session.
* **Forensic Significance:** Correlating matching Logon IDs across Event IDs (such as linking a successful logon `4624` with special privilege assignments `4672`) provides mathematical proof of session continuity, which is far stronger than relying solely on close timestamps[cite: 6].

---

## 4. Defensible Timeline Construction
* **Principle:** An investigator's goal is to build a rigorous, defensible timeline backed by hard log evidence (Logon IDs, PIDs, timestamps) rather than speculative narratives.
