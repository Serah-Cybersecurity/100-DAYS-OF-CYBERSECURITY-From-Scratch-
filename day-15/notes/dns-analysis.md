# Day 15 - Domain Name System (DNS) Protocol Forensics

## 1. DNS Purpose & Role

The **Domain Name System (DNS)** acts as the internet's directory service, translating human-readable Fully Qualified Domain Names (FQDNs, e.g., `api.github.com`) into machine-routable IP addresses (e.g., `140.82.121.4`). 

Because almost all network activity begins with a DNS lookup, DNS logs and packet streams are among the most critical hunting grounds for SOC analysts.

---

## 2. DNS Query & Response Architecture

DNS typically operates over **UDP port 53** (falling back to TCP port 53 for response payloads exceeding 512 bytes or DNSSEC zone transfers).

```
   Client Host (10.0.0.15)                           DNS Resolver (8.8.8.8)
        |                                                       |
        | ------- Standard Query: A example.com ---------------> | (TXID: 0x4a12)
        |                                                       |
        | <------ Standard Response: 93.184.216.34 ------------ | (TXID: 0x4a12)
```

---

## 3. Core DNS Resource Record Types

| Record Type | Full Name | Forensic & Operational Purpose |
| :--- | :--- | :--- |
| **A** | IPv4 Address Record | Maps a hostname to a 32-bit IPv4 address. |
| **AAAA** | IPv6 Address Record | Maps a hostname to a 128-bit IPv6 address. |
| **CNAME** | Canonical Name | Creates an alias pointing one domain to another domain. |
| **MX** | Mail Exchanger | Specifies mail servers responsible for accepting email for a domain. |
| **TXT** | Text Record | Carries human/machine readable text (used for SPF, DKIM, DMARC, and DNS Tunneling). |

---

## 4. Key Protocol Header Fields

* **DNS Transaction ID (TXID):** A 16-bit random identifier generated by the client to pair outgoing queries with incoming responses. Mismatched TXIDs indicate spoofing or dropped packets.
* **Time To Live (TTL):** A 32-bit integer defining how many seconds a resolver may cache the record before querying authoritative servers again. Threat actors use **Ultra-Low TTLs** (e.g., 0–10 seconds) for **Fast-Flux DNS** to rapidly rotate C2 IPs.
* **Response Codes (RCODEs):**
  * `NoError` (0): Lookup succeeded.
  * `NXDomain` (3): Non-Existent Domain; indicates the domain does not exist (frequently observed during DGA malware activity).
  * `ServFail` (2): Authoritative server failure.
  * `Refused` (5): Resolver policy refused the query.

---

## 5. DNS Security Threats & Forensic Artifacts

### 5.1 Domain Generation Algorithms (DGA)
Malware families (e.g., Conficker, Gameover Zeus) programmatically generate hundreds of pseudo-random domain names daily (e.g., `x89a1zqplv.com`) to establish C2 connections.
* **Forensic Indicator:** Massive spikes in `NXDomain` (RCODE 3) responses from a single internal endpoint.

### 5.2 DNS Exfiltration & Tunneling
Attackers use `TXT` or `A` record queries to send encoded data (Base64/Hex) out of restricted networks by embedding data in subdomains (e.g., `dGVzdGRhdGE=.attacker.com`).
* **Forensic Indicator:** High volume of unusually long subdomains, high entropy string queries, and excessive `TXT` record traffic.

---

## 6. Analytical Limitations of DNS

> ⚠️ **Key Boundary:** A DNS query proves *intent to resolve*, not successful data transfer.

1. **No Guarantee of Connection:** A host may resolve an IP address via DNS but never establish a TCP/UDP socket session with the destination.
2. **Encrypted DNS Blind Spots:** DNS-over-HTTPS (DoH) and DNS-over-TLS (DoT) encrypt queries over port 443/853, rendering standard PCAP DNS display filters (`dns`) blind to query contents without endpoint SSL key inspection.
